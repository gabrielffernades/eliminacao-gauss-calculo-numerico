2) APLICAÇÃO: balanceamento de carga em um cluster de 3 servidores
========================================================================
Cada servidor (A, B, C) tem hardware diferente. Queremos saber quantas
requisições por segundo (x, y, z) mandar para cada um de forma que:
  * o total atenda à demanda: 1200 req/s;
  * a CPU do cluster seja totalmente aproveitada: 3400 ms de CPU por segundo
    (cada requisição gasta 2 ms em A, 3 ms em B e 4 ms em C);
  * o link de rede de 930 Mbps seja totalmente aproveitado
    (0,5 Mbps por requisição em A, 0,8 em B e 1,2 em C).

Modelo:
     x +    y +    z = 1200
    2x +   3y +   4z = 3400
  0.5x + 0.8y + 1.2z =  930

Matriz aumentada inicial:
[   1    1    1  |  1200 ]
[   2    3    4  |  3400 ]
[ 0.5  0.8  1.2  |   930 ]

L1 <-> L2

Passo 1: zerando abaixo do pivô (coluna 1)
L2 <- L2 - (0.5)*L1
L3 <- L3 - (0.25)*L1
[ 2     3    4  |  3400 ]
[ 0  -0.5   -1  |  -500 ]
[ 0  0.05  0.2  |    80 ]

Passo 2: zerando abaixo do pivô (coluna 2)
L3 <- L3 - (-0.1)*L2
[ 2     3    4  |  3400 ]
[ 0  -0.5   -1  |  -500 ]
[ 0     0  0.1  |    30 ]

Retrossubstituição:
x1 = 500
x2 = 400
x3 = 300

Resíduo ||b - Ax||_inf = 0.00e+00

Interpretação: o balanceador deve enviar 500 req/s ao servidor A, 400 req/s ao B e 300 req/s ao C.

3) APLICAÇÃO: PageRank como sistema linear
========================================================================
O PageRank de cada página é a chance de um "navegador aleatório" estar
nela. Ele satisfaz  r = d*M*r + (1-d)/n,  ou seja, o sistema linear

    (I - d*M) r = (1-d)/n * [1, 1, ..., 1]

onde M[i][j] = 1/(nº de links da página j) se j aponta para i, e d = 0,85.

  Home     -> Blog, Loja, Sobre
  Blog     -> Home, Loja
  Loja     -> Home, Contato, FAQ
  Contato  -> Home
  Sobre    -> Home, Blog
  FAQ      -> Loja, Contato

Página     PageRank (Gauss)   PageRank (potência)
  Home       0.305267           0.305267
  Loja       0.215602           0.215602
  Blog       0.158877           0.158877
  Contato    0.122674           0.122674
  Sobre      0.111492           0.111492
  FAQ        0.086087           0.086087
Soma dos PageRanks = 1.000000 (deve ser 1)
Diferença máxima entre os dois métodos: 1.89e-13 (método da potência levou 35 iterações)

4) ANÁLISE DE PRECISÃO
========================================================================
4a) Sistema  1e-20*x1 + x2 = 1  e  x1 + x2 = 2
    Solução real: x1 ~ 1, x2 ~ 1
    Sem pivoteamento:       x1 = 0.000000, x2 = 1.000000   (ERRADO)
    Com pivoteamento parcial: x1 = 1.000000, x2 = 1.000000   (correto)
    Motivo: dividir por um pivô ~0 gera o multiplicador 1e20, e o "1" da
    segunda equação some no arredondamento do float (precisão ~1e-16).

    10          0.0001            0.0000               0.00000          2.2e-16
    25          0.0003            0.0001               0.00000          2.2e-16

   100          0.0123            0.0007               0.00004          5.6e-16

   400               -            0.0179               0.00051          2.4e-15
   800               -            0.1389               0.00235          2.6e-15

    (fatoração LU = Gauss com pivoteamento), só que em código compilado e
    otimizado para o processador.

6) COMPARAÇÃO: Gauss (direto) x Jacobi e Gauss-Seidel (iterativos)
========================================================================
Sistema 50x50, diagonal dominante: True
  Eliminação de Gauss  iterações:    -   erro máximo: 1.78e-15
  Jacobi               iterações:   15   erro máximo: 5.45e-12
  Gauss-Seidel         iterações:   11   erro máximo: 8.09e-13
    O método direto chega à resposta num número fixo de passos. Os iterativos
    vão se aproximando aos poucos e só têm convergência garantida em casos
    especiais (como diagonal dominante), mas gastam pouca memória e são
    preferidos em sistemas enormes e esparsos.
